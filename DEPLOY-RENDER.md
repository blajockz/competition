# Deploy on Render (free, no domain needed)

Result: the app runs at `https://<service>.onrender.com` with HTTPS, built from
your GitHub repository. Every `git push` redeploys it.

`render.yaml` (a Render *Blueprint*) already describes the service: free plan,
Frankfurt, Dockerfile build, health check `/api/health`, one instance, and all
the settings that are not secret.

---

## 1. Create the database tables (once)

Supabase dashboard → **SQL Editor** → New query → paste the whole content of
`supabase/schema.local.sql` → **Run**.

> `schema.local.sql` contains your secret. It is in `.gitignore`: never push it.

## 2. Put the code on GitHub

Create an **empty private** repository on GitHub (no README), then in the
project folder:

```bash
git init -b main
git add .
git status            # .env and supabase/schema.local.sql must NOT be listed
git commit -m "Competition platform"
git remote add origin https://github.com/<your-user>/<your-repo>.git
git push -u origin main
```

## 3. Create the service from the Blueprint

1. Sign in at <https://dashboard.render.com> (with GitHub is easiest).
2. **New** → **Blueprint**.
3. Connect GitHub if asked and give Render access to your repository, then
   select it (branch `main`). Render reads `render.yaml`.
4. Render asks for the values marked secret. Copy them from your local `.env`:

   | Name | Where to find it |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | `.env` |
   | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `.env` |
   | `APP_SYNC_SECRET` | `.env` (same value as in `schema.local.sql`) |
   | `ADMIN_ACCESS_CODE` | `.env` |
   | `HOST_ACCESS_CODE` | `.env` |

   `TOKEN_SECRET` is generated by Render; the other settings come from `render.yaml`.
5. **Apply** / **Deploy Blueprint**.

The first build takes a few minutes. In the service **Logs** you should see:

```
State loaded from supabase (version …)
Competition platform listening on http://0.0.0.0:8080  (storage: supabase)
```

Your address is shown at the top of the service page:
`https://competition-xxxx.onrender.com` → the public page.
Staff: `/admin` (admin code) and `/host` (host code). Teams: `/play`.

To change the name shown on the site, edit `EVENT_NAME` in the service's
**Environment** tab (or in `render.yaml` before creating the Blueprint).

---

## Good to know

- **Sleep**: free services sleep after **15 minutes without requests** and
  take about **a minute** to wake up. Open the site a few minutes before the
  event. While the event runs, every open screen sends a small keep-alive
  request every 4 minutes, so it stays awake.
- **Free hours**: 750 per month per workspace, shared by all your free
  services. One service running non-stop uses about 720, so keep only one
  free service awake at a time (sleeping services use no hours).
- **Nothing is lost** on sleep or restart: every change is saved to Supabase
  and reloaded on start. (Render's disk is wiped on restart; the app does not
  rely on it.)
- **Never run two copies against the same Supabase project**: each copy keeps
  its own live state and they would overwrite each other. A test copy needs
  its own Supabase project with `schema.sql` run in it.
- **Supabase free projects pause after a week without activity.** If the logs
  show "Supabase not reachable", restore the project in the Supabase dashboard,
  then **Manual Deploy → Restart service** on Render.
- **Update the app**: `git push` → Render rebuilds and redeploys.
- **Change a code or secret**: service → **Environment** → edit → save
  (it redeploys). If you change `APP_SYNC_SECRET`, run `supabase/schema.sql`
  again with the new value in the Supabase SQL editor.
